## 追加：死机 bug（gcd 小数参数无限循环）

用户报告输入 a=0.3, b=0.6, c=0.3 死机。

根因：delta=0 → isInteger 分支 `simplifyFraction(-0.6, 0.6)` → `gcd(0.6, 0.6)`。gcd 的位运算 `a|b`、`a>>=1` 会把小数截断为 0（ToInt32），`(0&1)===0` 恒真且 0>>1 仍为 0 → 第一个 while 无限循环。任何小数系数 + delta 为完全平方（整数 sqrt）的组合都会触发（如 1,-1.2,0.36 / 0.2,0.8,0.8）。

修复（同一文件两处）：
1. **根本修复**：isInteger 分支 3 处浮点 `simplifyFraction(-b±sqrtD, 2a)` 改为精确分数 `rootFrac(sign)`（x = ((-bFrac.num ± sqrtD*bFrac.den) * aFrac.den) / (bFrac.den * 2*aFrac.num)），与 tryRationalSqrtExact 分支思路一致。
2. **gcd 防御**：gcd 开头 `if (!Number.isInteger(a) || !Number.isInteger(b)) return 1`，杜绝任何未来路径死机。

验证：回归脚本扩至 24 用例全 PASS（新增 22=0.3,0.6,0.3→-1 / 23=1,-1.2,0.36→3/5 / 24=0.2,0.8,0.8→-2 / 25=0.5,1.5,1 有理平方），gcd(0.6,0.6)=1 且整数路径 gcd(30,30)=30 不受影响。

### 追加：gcd 防御的类型错误修复
`Number.isInteger` 在该项目 .ux 类型环境报错（`Property 'isInteger' does not exist on type '(value: any) => number'`，Number 被解析为函数类型）。改为项目惯用写法 `Math.floor(a) !== a`（Home/Statistics 等页面均用此模式），语义等价：小数返回 1 不化简、NaN 也安全返回 1、整数路径不变。24 用例复跑全 PASS。**项目约定：.ux 脚本内禁用 Number.isInteger，整数判断统一用 Math.floor(x) === x。**
