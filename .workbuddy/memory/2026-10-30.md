## 修复函数绘图陡线空白（`src/pages/Advanced/Graph/index.ux`）

- 根因：`drawCurves` 的 `jumpThreshold = (height/scale)*0.5`（数学单位，默认 10）配合 1px 采样
  （`Δx = 1/scale`），使斜率 > 200 的相邻采样全部被判「不连续」→ 只有 moveTo 没有 lineTo →
  整条曲线不落墨（`y=300x` 画布全空）。次因：`screenY` 超出 `[-100, height+100]` 直接抬笔。
- 改法：**越界改裁剪，不再抬笔**。新增 `COORD_LIMIT=1e7`（坐标钳制）、`CLIP_MARGIN=2`；
  `drawSingleCurve` 重写为 `emit()` 内做 Liang–Barsky 裁剪（`clipSegment` 返回 `[x0,y0,x1,y1,是否被裁]`），
  只有真极点才抬笔，两条判据：
  1. 一端被钳制（wild，≈落在极点）且另一端在可视区、分居画布中心两侧 → 断；
  2. 两端都跑出可视纵向范围时做 `isPoleJump`：**二分后跳变是否收敛**（连续函数二分后跳变至少减半，
     跨极点不收敛）。比「区间内部幅值极大」判据稳，能认极点贴着采样点的情形。
- 验证（Node 侧把 `<script>` 抽出直接 require 跑）：`300x/600x/1e6x/1e9x` 从 0 段变满屏竖线；
  平滑函数（sin/cos/x^2/x^3/2x+1/exp/ln/log/sqrt/abs/1/x）光栅化后与旧版**像素级完全一致**；
  `tan(x)`/`tan(pi*x)` 极点处无贯穿假竖线（旧版 0 段、初版 2/20 段，现 0 段）；耗时 < 0.4ms/帧（桌面）。

## 修复首页计算器「结果 → π → =」预览框拼接（`src/pages/Home/index.ux`）

- 根因：`inputConstant` 未像 `inputNumber` 那样在结果态重置 `expression`/`history`，
  等号把常量追加到旧结果后 → 预览行 `123.231 3.14159265359 =`，求值器只取首项，
  **还把垃圾记录写进历史**。同源 bug：`pendingFunction` 分支先算函数又把结果 push 进 expression。
- 改法：结果态（`waitingForOperand && expression.length === 1`）输入常量 → 清空 `expression`/`history`；
  挂起函数时先把常量写进 `display` 再 `executePendingFunction()` 并 return。π 仍以数值进出表达式。

## 同轮追加修复（用户确认范围：计算器 1/2/3 + 绘图 5/6 + 提示健壮性 7/8）

首页 `src/pages/Home/index.ux`：
- 抽 `dropFinishedResult()`：结果态改数字（`⌫`/`±`/`%`/常量）一律丢弃旧表达式，
  否则 `5+5= → ⌫(显示1) → ×2=` 得 20、`±` 得 20、`%` 得 20（应 2/-20/0.2）。
- 抽 `setError()` 统一 Error 态（display/error/expression/pendingFunction/waitingForOperand），
  `calculate` 与 `executePendingFunction` 共用：修掉 `tan(90)` 不置 `error`、`1e16×1e16` 把
  `'Error'` 存进表达式并写进历史的脏记录；`sqrt/log/ln` 的重复前置判断随之下线。
- `scientificFunction` 不再先执行挂起的上一个函数：连按 `sin→cos` 不再写 `sin(0)=0` 幽灵历史。

绘图 `src/pages/Advanced/Graph/index.ux`：
- 优先级重排：`parseTerm → parseUnary → parsePower → parseAtom`，修 `-x^2` 被算成 `(-x)^2`
  （`-x^2+4` 现在开口向下）；`2^-2`、`2^3^2` 右结合仍正确。
- `tokenize` 支持科学计数法（`1e6`/`2.5E-3`，仅当 e 后确有数字），`preprocessExpression`
  补 `letter→digit` 隐式乘（`x2`→`x*2`、`pi2`→`pi*2`）并对指数位让路；非法数字（`5..2`/`.`）标坏 token。
- `compileExpr` 增加整体校验（`pos` 必须走完 token），非法表达式返回 null 而不再静默算出错值。
- `drawGraph` 新增 `errorHint`：空输入 / 全部非法 → 停在输入页并提示；部分非法 → 进结果页但在
  输入页与结果页都显示「f₂ 表达式有误」。`updateDisplayExpr` 一编辑即清空提示。
  新增 i18n key `graph.empty_expr` / `graph.invalid_expr`（zh-CN / zh-TW / en）。
- `doDrawGraph` 取不到 canvas 不再直接 return（会把 `isLoading` 卡死在 true）：归零遮罩并按
  `retryCount < 5` 重排，成功绘制后 `retryCount` 归零。
- 遗留未修（用户本轮未选）：静态输入框截断会留下 `…(x)+cos(x)` 的孤字符（L436）、`evalExpr` 死代码、
  Home 缺 `onDestroy` 清弹窗定时器、重绘保留上次缩放。

## 计算结果千分位（新功能）

- 思路：`display` 继续存**原始数字串**（`parseFloat`/退格/表达式/历史都用它），新增 `displayText`
  只做显示层格式化；所有 `this.display = X` 改为 `setDisplay(X)`（14 处 + `inputDecimal` 里的
  `this.display += '.'` 这种复合赋值容易漏，必须一起收口）。模板绑 `displayText`。
- `addThousandSep(str)`：只匹配 `^-?\d+(\.\d*)?$`，负数/小数/末尾小数点都保留，Error 与科学计数法原样返回。
- 新增 `global.thousandSeparator`（默认 `true`，老配置里缺字段按开启）；`loadSettings`/`saveSettings` 同步；
  设置页开关放在**角度模式那一张卡片正下方**，不单列「显示」分区（该 i18n key 已删），
  `onShow` 回首页时 `setDisplay(this.display)` 重新格式化。
- 验证：边输入边分组 `1→12→123→1,234→12,345→12,345.`（末位小数点保留）→`12,345.67`；结果
  `123456789×10 → 1,234,567,890`，而表达式与历史仍存原始 `1234567890`；关闭开关立即回到纯数字；
  之前修的 ⌫/±/%/π/Error 行为全部未回归。
